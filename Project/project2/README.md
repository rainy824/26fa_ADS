# 三种堆实现 Dijkstra：项目设计

## 当前状态

项目使用 C。目前已有 `BinomialQueue.c/.h`（只保存整数键），`Dijkstra.c` 尚未实现。本文确定模块边界与实验方法；不代表三种算法已经完成或测得性能结果。

## 实现顺序

1. 图的邻接表、非负整数边权输入、朴素 O(V² + E) Dijkstra 参考实现。
2. 支持顶点定位和 decrease-key 的二叉最小堆，接入统一 Dijkstra。
3. 改造现有二项堆，增加顶点编号、父指针、定位表及资源释放。
4. 斐波那契堆：根链表、合并同度树、切割及级联切割。
5. 正确性对照、随机图生成、计时及 CSV 结果导出。

每一步先解释结构与操作，再实现、编译并验证。

## 模块边界

| 文件（计划） | 职责 |
| --- | --- |
| `Graph.c/.h` | 邻接表；读图和释放资源 |
| `PriorityQueue.h` | 三种堆共用的操作约定 |
| `BinaryHeap.c/.h` | 数组二叉堆及顶点位置表 |
| `BinomialQueue.c/.h` | 二项堆及顶点节点表 |
| `FibonacciHeap.c/.h` | 斐波那契堆及顶点节点表 |
| `Dijkstra.c/.h` | 共用堆版算法、朴素参考算法 |
| `test.c` | 堆操作测试、最短路对照 |
| `benchmark.c` | 图生成、计时、统计和 CSV 输出 |

三种堆共享一份 Dijkstra 流程。图先构造一次，再交给不同堆的算法运行，不在计时过程中生成或读取图。

## 数据约定

- 顶点编号从 0 到 V-1；初期使用有向图。无向边通过添加两条有向边表达。
- 边权非负；允许零权、自环、重边及不可达顶点，负权输入必须拒绝。
- 距离使用 `int64_t`，`INT64_MAX` 表示不可达；有限距离必须小于该值。松弛前检查加法溢出，超出可表示范围时返回错误，不将其悄悄视为不可达。
- 优先队列元素保存 `(distance, vertex)`；先按距离比较，同距离按顶点编号比较，保证三种实现顺序一致。
- 每个未确定最短距离的顶点至多有一个在堆中的元素。首次发现时插入，后续变短调用 decrease-key，取出后不再入堆。
- 三种堆都支持 create、insert、extract-min、decrease-key、is-empty、destroy。算法只按顶点编号操作，不访问堆的内部节点。
- 二叉堆用 `position[vertex]` 定位；两个链式堆用 `node_of[vertex]` 定位。二项堆上浮交换时必须同时交换顶点与距离并更新定位表，不能只交换距离。
- 图、堆和最短路结果分别拥有自己的资源；所有失败路径与正常结束都要释放资源。

## 理论预期

下表按每个顶点最多一次插入、一次取出，以及最多 E 次成功松弛给出常用上界。

| 堆 | insert | extract-min | decrease-key | Dijkstra |
| --- | --- | --- | --- | --- |
| 二叉堆 | O(log V) | O(log V) | O(log V) | O((V + E) log V) |
| 二项堆 | O(log V) | O(log V) | O(log V) | O((V + E) log V) |
| 斐波那契堆 | O(1) 摊还 | O(log V) 摊还 | O(1) 摊还 | O(E + V log V) 摊还 |

这些是复杂度预期，不能直接当作实际运行时间排名。二叉堆的连续内存布局通常有较低常数开销；斐波那契堆是否胜出需要测量。

## 正确性验证

1. 堆：空堆、单节点、重复键、连续 decrease-key、取出顺序、清空及重复创建销毁。
2. 二项堆：根的度数、父子关系、堆序、节点总数、最小根缓存与定位表一致性。
3. 斐波那契堆：双向循环链表、父子关系、degree、mark、堆序与定位表一致性，覆盖级联切割。
4. 小图三种实现与朴素 Dijkstra 比较全部距离；随机测试使用固定种子。
5. 图覆盖零权、自环、重边、不可达、单顶点、多次改善同一顶点，以及距离溢出边界。

## 性能实验

- 分别改变 V、E 和权重范围，区分稀疏图、中等密度图及可承受规模的稠密图。
- 随机图使用固定种子，并记录是否保证源点可达全部顶点；明确 E 表示有向边记录数。
- 同一个图、源点及编译优化选项下比较三种堆。正式计时使用优化构建，并记录编译器版本、操作系统与处理器。
- 每组先预热，再重复运行；轮换三种堆的运行顺序。报告中位数及四分位范围，避免只取一次结果。
- 主要计时包含堆创建、算法执行及堆销毁；距离和前驱数组提前分配，其初始化计入时间。图构造、正确性对照和结果打印排除在计时外。
- 正确性验证通过后才接受计时结果；计数统计单独运行，避免给正式计时增加计数开销。
- 记录 insert、extract-min、decrease-key 次数与最大堆大小，解释测试图是否真的产生足够多的 decrease-key。
- CSV 建议字段：heap,V,E,seed,source,weight_max,trial,time_ms,inserts,extracts,decreases,peak_size。
- 如比较内存，分别报告峰值活动节点、预分配容量和估算字节数；不要把节点数直接视为内存占用。

结论应说明各实测图族与规模下的表现，并结合操作次数和实现开销解释结果。
